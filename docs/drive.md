# «Диск ядра»: Google Drive в Atom

Коннектор связывает Atom с Google Drive. Есть два входа:

- **приложение «Диск»** в каталоге (⊞): папки, загрузка файлов, отметки «кому из операторов что открыто» —
  это основное место работы;
- **окно «Команда» → «Доступ» → «Диск ядра»** — то же самое правами, рядом с остальными правами оператора.

По умолчанию связь **только на чтение**. Загрузка и создание папок включаются отдельно (`GDRIVE_WRITE=1`
и токен с правом `drive`); удалять файлы и менять доступы Atom не умеет — это осознанно.

- Код: [`jarvis/gdrive.py`](../jarvis/gdrive.py), окно — [`static/drive.js`](../jarvis/webapp/static/drive.js)
- Права операторов: `jarvis/operators.py` (`drive`), доступ — `Jarvis.op_drive*` в `jarvis/core.py`
- API: `/api/gdrive` (владелец), `/api/op/drive` (оператор)
- Панель: окно «Команда» → оператор → «Доступ» → «Диск ядра»

## Как это выглядит

1. Владелец открывает **приложение «Диск»** (⊞ → Диск), ходит по папкам, создаёт свои, загружает файлы.
2. Кнопка **«Доступ»** у папки или файла — кому из операторов открыто и на каком уровне.
3. Оператор открывает «Диск» в своём каталоге приложений (или вкладку «Диск» в кабинете) — видит ровно
   выданные папки, без ваших данных, и может загружать туда, где разрешено.

Уровни доступа:

| Что выдаём | Уровни | Что получает оператор |
|---|---|---|
| Папка | `view` — просмотр | видит содержимое папки и вложенных папок, читает документы и тексты |
| Папка | `upload` — просмотр и загрузка | то же + загружает фото, видео и файлы **в эту папку** |
| Файл | `view` — просмотр | открывает один файл, не зная, откуда он и чей |
| Файл | `copy` — просмотр и копия | ещё и «Сохранить копию к себе» — заметкой в `Команда/<Имя>/Диск/` |

Папка открывает своё поддерево. Проверка «внутри ли файл выданной папки» идёт на сервере по цепочке
родителей (`Drive.is_within`), поэтому оператор не может запросить соседнюю папку или корень Диска.

## Настройка (один раз, на компьютере)

Нужен аккаунт Google, у которого лежат файлы, и доступ к [Google Cloud Console](https://console.cloud.google.com/).

### 1. Проект и API

1. Создайте проект (или выберите существующий).
2. **APIs & Services → Library → Google Drive API → Enable.**

### 2. Экран согласия

1. **APIs & Services → OAuth consent screen**: тип **External**, название — любое («Atom»).
2. В **Test users** добавьте свой аккаунт Google (для External в режиме Testing это обязательно).
3. Право нужно одно: `.../auth/drive.readonly` — скрипт запросит его сам.

Внутренний (Internal) тип подходит, если у вас Google Workspace: тогда тестовые пользователи не нужны.

### 3. Клиент OAuth

**APIs & Services → Credentials → Create credentials → OAuth client ID**:

- тип приложения — **Desktop app** (не Web: для desktop разрешён адрес `http://127.0.0.1` без HTTPS);
- сохраните **Client ID** и **Client secret**.

### 4. Refresh-токен

На компьютере, в корне репозитория:

```bash
GDRIVE_CLIENT_ID=… GDRIVE_CLIENT_SECRET=… python3 scripts/gdrive_auth.py --write
```

Скрипт откроет страницу согласия, поймает код на `http://127.0.0.1:8767/` и впишет
`GDRIVE_REFRESH_TOKEN` в `.env`. Без `--write` просто напечатает строку для вставки руками.

Если браузер не открылся — скопируйте ссылку из терминала. Если порт занят: `--port 8768`.

### 5. Включить в Atom

В `.env`:

```ini
GDRIVE_ENABLED=1
GDRIVE_CLIENT_ID=…
GDRIVE_CLIENT_SECRET=…
GDRIVE_REFRESH_TOKEN=…
# пусто — весь Диск; иначе id одной папки (из ссылки drive.google.com/drive/folders/<ID>)
GDRIVE_FOLDER_ID=
GDRIVE_MAX_MB=4
# 1 — загрузка файлов и создание папок (нужен токен с правом drive, см. шаг 4а)
GDRIVE_WRITE=0
```

Токен: `python3 scripts/gdrive_auth.py --write` — только чтение; для загрузки
`python3 scripts/gdrive_auth.py --can-upload --write` и `GDRIVE_WRITE=1`. Без права `drive` кнопки
загрузки в приложении неактивны, а сервер честно отвечает, чего не хватает.

Перезапустите Atom. В окне «Команда» блок «Диск ядра» покажет файлы; если нет — там же будет причина
(какого параметра не хватает или что ответил Google).

## Анонимность ядра

Оператор не должен понимать, чей это Диск и где лежит файл. Это обеспечивает сервер, а не интерфейс:

| Что | Оператору |
|---|---|
| Имя файла, вид (документ/таблица/текст), размер, дата изменения | видит |
| Текст открытого файла | видит (только если владелец открыл именно этот файл) |
| Почта и имя владельца аккаунта | **не видит** |
| `owners`, `permissions`, `sharing` из ответа Google | **не видит**: `Drive._item()` собирает ответ по белому списку полей, лишнее не попадает даже в память |
| Путь по Диску, родительские папки, id папок | **не видит** |
| Ссылка `webViewLink` и доступ к другим файлам | **не видит** |
| Наличие остальных файлов на Диске | не знает: список приходит только из выдачи |

В заметке-копии стоит `source: Диск ядра` — без имени аккаунта, почты и пути.

## Личные заметки

«Диск ядра» не открывает доступ к хранилищу. Правила остаются прежними:

- личные заметки оператора — только его папка `Команда/<Имя>/`;
- заметки владельца открываются отдельно, списком «Доверенные заметки» (только чтение или с правкой);
- копия файла с Диска ложится **только** в папку оператора `Команда/<Имя>/Диск/` — в заметки владельца
  и в общие проекты она не попадает;
- выдача файла Диска не даёт доступа ни к одной заметке, и наоборот.

## API

| Метод | Кто | Что делает |
|---|---|---|
| `GET /api/drive?folder=&q=` | владелец | содержимое папки: папки и файлы |
| `GET /api/drive/file/{id}` | владелец | текст документа |
| `GET /api/drive/raw/{id}` | владелец | картинка для превью |
| `POST /api/drive/mkdir` | владелец | создать папку (`name`, `parent`) |
| `POST /api/drive/upload` | владелец | загрузить файл (форма: `file`, `folder`) |
| `POST /api/drive/share` | владелец | выдать/изменить доступ (`op`, `id`, `name`, `kind`, `level`, пусто — убрать) |
| `GET /api/gdrive?q=&folder=` | владелец | то же для окна «Команда» (плоский список) |
| `GET /api/op/drive/list?folder=` | оператор | корни-выдачи или содержимое выданной папки |
| `POST /api/op/drive/upload` | оператор | загрузка в папку с уровнем «upload» |
| `GET /api/op/drive/raw/{id}` | оператор | картинка из выданного |
| `GET /api/op/drive` | оператор | выданные ему файлы: `id`, `name`, `level` |
| `GET /api/op/drive/{id}` | оператор | текст файла; чужой id — 403, до Google запрос не уходит |
| `POST /api/op/drive/{id}` `{"action":"save"}` | оператор | копия в `Команда/<Имя>/Диск/` (только уровень «копия») |

Ошибки коннектора — `DriveError` (наследник `ValueError`), поэтому веб отдаёт их как `400` с текстом на
русском: «не подключён», «токен не принял», «нет права drive.readonly», «файл больше N МБ».

## Ограничения

- **Запись — по желанию и по праву.** Без `GDRIVE_WRITE=1` и права `drive` коннектор только читает.
  С ними доступны загрузка файлов и создание папок; удаления и смены прав на Диске в Atom нет.
- **Просмотр — текст и картинки.** Документы Google экспортируются в markdown, текстовые файлы читаются как есть,
  картинки показываются превью (до 8 МБ). PDF, таблицы, презентации и видео открыть внутри Atom нельзя —
  их место на Диске; загружать видео можно (до 32 МБ).
- **Папка — это поддерево.** Положили новый файл в выданную папку — оператор его увидит. Поэтому выдавайте
  папку, в которую не складываете лишнего, или отдельную папку для обмена.
- **Размер.** Текст в заметке — до `GDRIVE_MAX_MB` (4 МБ, максимум 20); загрузка на Диск — до 32 МБ.
- **Нет интерактивного входа.** Refresh-токен выпускается один раз скриптом; OAuth-флоу в браузере Atom
  не делает (в режиме «только iPhone» коннектор недоступен — это серверная часть).

## Безопасность

- Refresh-токен = постоянное чтение всего Диска аккаунта. Храните его как пароль: `.env` (файл в
  `.gitignore`), не в заметках, не в переписке, не в issue.
- Токен можно отозвать в любой момент: [myaccount.google.com/permissions](https://myaccount.google.com/permissions)
  → «Atom» → удалить доступ. После этого коннектор скажет «Google не принял токен».
- В логах и в API токен не появляется: наружу уходят только сообщения об ошибках.
- Ограничение одной папкой (`GDRIVE_FOLDER_ID`) уменьшает и объём выдачи, и последствия утечки токена.

## Если не работает

| Симптом | Причина и что делать |
|---|---|
| «Диск не подключён: нужны GDRIVE_CLIENT_ID…» | не заполнен `.env` или Atom не перезапущен |
| «Google не принял токен» | токен отозван или выпущен для другого client_id — повторите шаг 4 |
| «у токена нет права drive.readonly» | при согласии не отметили галочку доступа к Диску — отзовите доступ и повторите |
| Список пуст | либо `GDRIVE_FOLDER_ID` указывает на пустую папку, либо у аккаунта нет файлов, кроме папок |
| «файл больше N МБ» | поднимите `GDRIVE_MAX_MB` (до 20) или откройте файл на Диске |
| «так можно открыть документ Google или текстовый файл» | PDF/картинки/таблицы не поддерживаются |
