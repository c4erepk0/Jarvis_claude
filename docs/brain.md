# Мозг Jarvis: GigaChat, YandexGPT или Claude

Без модели Jarvis понимает только команды («добавь задачу…», «потратил 450 на кофе», протоколы).
С моделью — свободную речь: сам решает, какие инструменты вызвать (задачи, траты, заметки, поиск по памяти,
статус проектов, протоколы), и отвечает в манере дворецкого.

| | GigaChat (Сбер) | YandexGPT (Яндекс AI Studio) | Claude (Anthropic) |
|---|---|---|---|
| Доступ из России | да | да | официально нет |
| Оплата | российская карта; для физлиц есть бесплатный пакет (условия — на сайте Сбера) | российская карта, по токенам | — |
| Что нужно | «Ключ авторизации» | API-ключ + ID каталога | `ANTHROPIC_API_KEY` |
| Фото чеков | пока нет | пока нет | да |

Работает в серверном режиме (VPS, `scripts/vps.sh`). В режиме «только iPhone» (GitHub Pages) — только Claude:
браузер не может обращаться к GigaChat и YandexGPT напрямую.

## GigaChat

1. Откройте **developers.sber.ru** → войдите по Сбер ID → создайте проект **GigaChat API**
   (для физлиц — тип доступа `GIGACHAT_API_PERS`).
2. В настройках API проекта нажмите «Получить ключ» и скопируйте **«Ключ авторизации»** (Authorization key).
   Его показывают один раз.
3. На сервере:
   ```bash
   bash /opt/jarvis/scripts/vps.sh brain
   ```
   Ответьте `1`, вставьте ключ (ввод скрыт), тип доступа — Enter. Jarvis перезапустится и сразу ответит
   на проверочный вопрос.

Модель по умолчанию — `GigaChat-2-Max`. Если она недоступна на вашем тарифе, в `/opt/jarvis/.env` поставьте
`GIGACHAT_MODEL=GigaChat-2-Pro` (или `GigaChat-2-Lite`) и `systemctl restart jarvis`.

TLS у GigaChat — на сертификате Минцифры. Он уже лежит в `jarvis/certs/` и подключается только к запросам
GigaChat (а не ко всему серверу), ставить его в систему не нужно.

## YandexGPT

1. Откройте **aistudio.yandex.ru** → войдите с Яндекс ID → создайте платёжный аккаунт и каталог.
2. Создайте **API-ключ** в AI Studio (у ключа должны быть права на модели — роль `ai.languageModels.user`).
3. Скопируйте **ID каталога** (начинается с `b1g…`; виден, если навести на имя каталога вверху).
4. На сервере:
   ```bash
   bash /opt/jarvis/scripts/vps.sh brain
   ```
   Ответьте `2`, вставьте ключ и ID каталога.

Модель по умолчанию — `yandexgpt/rc` (YandexGPT Pro). Другая: `YANDEX_MODEL=yandexgpt-5-pro`,
`aliceai-llm` и т.п. — список в документации AI Studio.

## Проверка и неполадки

- `bash /opt/jarvis/scripts/vps.sh check` — доступны ли GigaChat и YandexGPT с сервера.
- `bash /opt/jarvis/scripts/vps.sh logs` — журнал; ошибки модели пишутся с её именем.
- «не принял ключ» — ключ скопирован не полностью или отозван; повторите `vps.sh brain`.
- «недоступен: лимит запросов» — подождите минуту; «нет связи» — см. `check`.
- Если задано несколько ключей, выбирает `JARVIS_LLM=gigachat|yandex|claude`; без неё — первый из
  Claude → GigaChat → YandexGPT, для которого есть ключ.
- Простые команды Jarvis выполняет сам, без модели (`JARVIS_LOCAL_FIRST=1`): быстрее и не тратит токены.

## Как устроено (для разработки)

`jarvis/brain.py` ведёт разговор одинаково для всех моделей: личность, служебная строка со временем,
инструменты, история только дописывается, отклонённый ход не остаётся в истории. `jarvis/llm.py` переводит
в формат API: GigaChat — `functions` / `function_call` (+ `functions_state_id`) / роль `function`,
OAuth-токен на 30 минут; YandexGPT — OpenAI-совместимые `tools` / `tool_calls` / роль `tool`,
заголовки `Api-Key` и `OpenAI-Project`. Тесты с поддельными API — `tests/test_llm.py`.
