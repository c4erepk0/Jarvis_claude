# Мозг Atom: GigaChat, YandexGPT, DeepSeek или Claude

Без модели Atom понимает только команды («добавь задачу…», «потратил 450 на кофе», протоколы).
С моделью — свободную речь: сам решает, какие инструменты вызвать (задачи, траты, заметки, поиск по памяти,
статус проектов, протоколы), и отвечает в манере дворецкого.

| | GigaChat (Сбер) | YandexGPT (Яндекс AI Studio) | DeepSeek | Claude (Anthropic) |
|---|---|---|---|---|
| Доступ из России | да | да | да | официально нет |
| Оплата | российская карта; для физлиц есть бесплатный пакет (условия — на сайте Сбера) | российская карта, по токенам | предоплата баланса, по токенам | — |
| Что нужно | «Ключ авторизации» | API-ключ + ID каталога | `DEEPSEEK_API_KEY` | `ANTHROPIC_API_KEY` |
| Фото чеков | пока нет | пока нет | пока нет | да |

Работает в серверном режиме (VPS, `scripts/vps.sh`). В режиме «только iPhone» (GitHub Pages) — только Claude:
браузер не может обращаться к GigaChat, YandexGPT и DeepSeek напрямую.

## GigaChat

1. Откройте **developers.sber.ru** → войдите по Сбер ID → создайте проект **GigaChat API**
   (для физлиц — тип доступа `GIGACHAT_API_PERS`).
2. В настройках API проекта нажмите «Получить ключ» и скопируйте **«Ключ авторизации»** (Authorization key).
   Его показывают один раз.
3. На сервере:
   ```bash
   bash /opt/jarvis/scripts/vps.sh brain
   ```
   Ответьте `1`, вставьте ключ (ввод скрыт), тип доступа — Enter. Atom перезапустится и сразу ответит
   на проверочный вопрос.

Модель по умолчанию — `GigaChat-2-Max`. Если она недоступна на вашем тарифе, в `/opt/jarvis/.env` поставьте
`GIGACHAT_MODEL=GigaChat-2-Pro` (или `GigaChat-2-Lite`) и `systemctl restart jarvis`.

TLS у GigaChat — на сертификате Минцифры. Он уже лежит в `jarvis/certs/` и подключается только к запросам
GigaChat (а не ко всему серверу), ставить его в систему не нужно.

## YandexGPT

1. Откройте **aistudio.yandex.ru** → войдите с Яндекс ID → создайте платёжный аккаунт и каталог.
2. Создайте **API-ключ** в AI Studio (у ключа должны быть права на модели — роль `ai.languageModels.user`).
3. Скопируйте **ID каталога** (начинается с `b1g…`; виден, если навести на имя каталога вверху).
4. На сервере:
   ```bash
   bash /opt/jarvis/scripts/vps.sh brain
   ```
   Ответьте `2`, вставьте ключ и ID каталога.

Модель по умолчанию — `yandexgpt/rc` (YandexGPT Pro). Другая: `YANDEX_MODEL=yandexgpt-5-pro`,
`aliceai-llm` и т.п. — список в документации AI Studio.

## DeepSeek

1. Откройте **platform.deepseek.com** → пополните баланс → **API keys** → создайте ключ (`sk-…`).
2. Задайте его одним из способов:
   - в Atom: ⚙ «Настройки» → раздел «Мозг» → **DeepSeek: API-ключ**, в «Какой мозг» — `deepseek`
     (или оставьте пустым, если других ключей нет) → «Перезапустить»;
   - на сервере: `bash /opt/jarvis/scripts/vps.sh brain`, ответьте `3` и вставьте ключ.

Модель по умолчанию — `deepseek-chat`. Рассуждающая: `DEEPSEEK_MODEL=deepseek-reasoner` (медленнее, для голоса
обычно не нужна). «закончились деньги» в ответе — пополните баланс на platform.deepseek.com.

## Своя модель (OpenRouter, прокси, Ollama)

Если удобнее одна подписка на всё или нужна модель, которой нет в списке, — подключите любую
**OpenAI-совместимую** модель. Atom не привязан к провайдеру: тот же формат `tools`/`tool_calls`.

```ini
LLM_URL=https://openrouter.ai/api/v1     # или http://127.0.0.1:11434/v1 (Ollama), свой прокси
LLM_KEY=sk-or-…
LLM_MODEL=anthropic/claude-sonnet-4.5   # имя модели у выбранного API
JARVIS_LLM=custom                        # необязательно: иначе выберется по ключу
```

- Подходит всё, что отвечает на `POST /chat/completions`: OpenRouter, агрегаторы с оплатой в рублях,
  локальный Ollama / LM Studio, корпоративный шлюз.
- Имя модели — ровно такое, как у провайдера; список удобно смотреть в его каталоге.
- Модель попадает в выбор на главном экране как «Своя модель»; переключение — без перезапуска.
- Для OpenRouter Atom добавляет заголовки `HTTP-Referer` и `X-Title` — так запросы видно в статистике.
- Если прокси не отвечает, Atom скажет «нет связи» и повторит запрос один раз; разговор не ломается.

## Выбор модели на главном экране

Под строкой команды — кнопка с активной моделью, например «Claude · Opus 5.5» или «DeepSeek · Chat»: именно она
ответит на следующий вопрос. По нажатию — список моделей тех провайдеров, у которых задан ключ (Claude: Opus,
Sonnet, Haiku, Fable; GigaChat 2 Max/Pro/Lite; YandexGPT Pro/Lite; DeepSeek Chat/Reasoner, плюс модель из
`.env`, если её нет в списке). Если ключ провайдера не приняли, рядом с ним — «ключ не принят».

Выбор действует сразу, без перезапуска, и запоминается (`data/settings.json`, раздел `brain`). Разговор при смене
модели начинается заново, но новая модель получает краткое резюме прошлого. Если ключ выбранного провайдера потом
убрать, Atom вернётся к модели по `JARVIS_LLM` / первому ключу. У Claude Haiku нет серверного фолбэка и поиска
в интернете — Atom их для неё не включает. В режиме «только iPhone» список — только модели Claude.

API: `GET /api/brain` — активная модель и список, `POST /api/brain {backend, model}` — выбрать (только владелец).

## Если Atom не запускается после смены настроек

Значения из окна «Настройки» хранятся в `data/settings.json` и накладываются поверх `.env`. Если с ними Atom
не может запуститься (например, опечатка в числе), он запускается без них и показывает ошибку в «Настройках».
Незнакомое имя в «Какой мозг» не роняет Atom: мозг выбирается по заданному ключу, в журнале — предупреждение.

## Что мозг умеет с заметками

- «Открой заметку про оферту» — найдёт и покажет её в голограмме.
- Открыли заметку в голограмме и сказали «сократи эту заметку», «добавь сюда пункт про цены», «поставь этот
  проект на паузу» — Atom знает, какая заметка открыта, читает её и правит точечно (инструмент `note_edit`
  меняет только конкретный фрагмент), новые заметки создаёт через `note_create`.
- Ответы для голоса очищаются от markdown — звёздочки и решётки не зачитываются.
- Если GigaChat или YandexGPT на секунду недоступны (сеть, перегрузка), Atom сам повторит запрос.

## Проверка и неполадки

- `bash /opt/jarvis/scripts/vps.sh check` — доступны ли GigaChat, YandexGPT и DeepSeek с сервера.
- `bash /opt/jarvis/scripts/vps.sh logs` — журнал; ошибки модели пишутся с её именем.
- «не принял ключ» — ключ скопирован не полностью или отозван; повторите `vps.sh brain`.
- «недоступен: лимит запросов» — подождите минуту; «нет связи» — см. `check`.
- Если задано несколько ключей, выбирает `JARVIS_LLM=gigachat|yandex|deepseek|claude`; без неё — первый из
  Claude → GigaChat → YandexGPT → DeepSeek, для которого есть ключ.
- Простые команды Atom выполняет сам, без модели (`JARVIS_LOCAL_FIRST=1`): быстрее и не тратит токены.

## Как устроено (для разработки)

`jarvis/brain.py` ведёт разговор одинаково для всех моделей: личность, служебная строка со временем,
инструменты, история только дописывается, отклонённый ход не остаётся в истории. `jarvis/llm.py` переводит
в формат API: GigaChat — `functions` / `function_call` (+ `functions_state_id`) / роль `function`,
OAuth-токен на 30 минут; YandexGPT — OpenAI-совместимые `tools` / `tool_calls` / роль `tool`,
заголовки `Api-Key` и `OpenAI-Project`; DeepSeek — тот же формат с `Authorization: Bearer`. Тесты с поддельными API — `tests/test_llm.py`.
